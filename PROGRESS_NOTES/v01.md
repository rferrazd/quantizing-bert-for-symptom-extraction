# Version 0.1

## Motivation

Version 0.0 failed primarily due to **extreme label sparsity**:

* ~3,500 distinct labels
* ~10 examples per label
* Strong dominance of the `"O"` class

This caused the model to converge to a trivial solution (predicting `"O"`), regardless of:

* model choice (DistilBERT vs BioBERT)
* freezing vs training all layers

Version 0.1 focuses on **reducing label complexity** so the model can first learn *what a symptom span looks like*, before learning *which specific symptom it is*.

---

## Key Change from v0.0

All training infrastructure remains the same **except for the dataset labels**.

### v0.0 Labels (too sparse)

```
B-SYMPTOM_s0004_NEG
I-SYMPTOM_s0004_NEG
```

### v0.1 Labels (collapsed)

```
B-SYMPTOM_NEG
I-SYMPTOM_NEG
B-SYMPTOM_POS
I-SYMPTOM_POS
O
```

* **Concept IDs are removed**
* Polarity (POS / NEG) is preserved
* BIO structure is preserved

---

## Expected Benefits

* Label count reduced from ~3,500 → **5**
* Each label now has **thousands of examples**
* Strong parameter sharing across all symptom mentions
* Model can meaningfully learn:

  * symptom boundaries
  * negation vs affirmation

This setup aligns better with how transformer-based NER models are typically trained.
